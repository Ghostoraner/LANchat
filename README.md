# LANChat

**LANChat** — кроссплатформенное приложение для обмена сообщениями в локальной сети (LAN).

Проект написан на **C# / .NET 10** с использованием **Avalonia UI** и использует архитектуру **Client–Server**. Обмен данными выполняется по TCP/IP в формате JSON.

> 🚧 Проект находится в разработке.

## ✨ Возможности

* 💬 Обмен сообщениями в реальном времени
* 🌐 Работа внутри локальной сети (LAN)
* 🖥️ Кроссплатформенность
  * Linux
  * Windows
* 👤 Никнеймы пользователей
* 🔔 Системные уведомления о подключении и отключении пользователей
* 📡 TCP-соединение между клиентом и сервером
* 📦 JSON-протокол для обмена данными
* 🎨 Графический интерфейс на Avalonia UI
* ⚡ Лёгкий сервер без сторонних backend-сервисов

### `LANChat.Server`

Консольный TCP-сервер, который:

* принимает подключения клиентов;
* регистрирует пользователей;
* отслеживает подключения и отключения;
* принимает сообщения;
* рассылает сообщения подключённым клиентам.

### `LANChat.Client`

GUI-клиент на **Avalonia UI**, который позволяет:

* подключаться к серверу;
* указывать IP и порт;
* задавать никнейм;
* отправлять сообщения;
* получать сообщения от других пользователей;
* отображать системные события.

## ⚙️ Требования

Перед запуском убедитесь, что установлен:

* **.NET 10 SDK** — скрипты установки могут установить его автоматически;
* Git;
* GUI-окружение на Linux (X11 или Wayland).

Проверить установленную версию .NET:

```bash
dotnet --version
```

## 📦 Установка с помощью скриптов

Скрипты нужно запускать из корневой папки репозитория. Они устанавливают необходимые системные пакеты, при необходимости скачивают **.NET SDK 10**, а затем собирают проект в конфигурации `Release`.

### Linux и Termux: `install.sh`

Скачайте репозиторий и перейдите в его каталог:

```bash
git clone https://github.com/Ghostoraner/LANchat.git
cd LANchat
```

Сделайте скрипт исполняемым и запустите его:

```bash
chmod +x install.sh
./install.sh
```

Что делает скрипт:

* определяет дистрибутив Linux или окружение Termux;
* устанавливает базовые зависимости (`git`, `curl`, `wget`, ICU и `zlib`) через соответствующий менеджер пакетов;
* для Debian/Ubuntu, Arch и Fedora использует `sudo`, поэтому у пользователя должны быть права администратора;
* скачивает .NET SDK 10, если команда `dotnet` ещё недоступна;
* добавляет `DOTNET_ROOT` и путь к .NET в `~/.bashrc` или `~/.zshrc`;
* собирает решение командой `dotnet build ... -c Release`.

После установки перезапустите терминал или загрузите настройки оболочки вручную, если .NET устанавливался скриптом:

```bash
source ~/.bashrc
# либо
source ~/.zshrc
```

В Termux скрипт устанавливает дополнительные пакеты для запуска графического приложения через Termux:X11. Для работы GUI также потребуется настроенное приложение Termux:X11.

### Windows: `install.ps1`

Откройте PowerShell, перейдите в каталог репозитория и запустите:

```powershell
Set-Location .\LANChat
.\install.ps1
```

Если PowerShell запрещает запуск локальных скриптов, разрешите выполнение скриптов только для текущего пользователя:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Затем снова выполните:

```powershell
.\install.ps1
```

Что делает скрипт:

* проверяет наличие команды `dotnet`;
* если .NET SDK не найден, скачивает официальный `dotnet-install.ps1` и устанавливает канал .NET 10 в `%USERPROFILE%\.dotnet`;
* временно добавляет установленный .NET в `PATH` текущего процесса PowerShell;
* собирает `LANChat.slnx` (или `LANChat.sln`, если первый файл отсутствует) в конфигурации `Release`.

> ⚠️ Скрипты выполняют установку зависимостей и сборку, но не создают ярлыки и не запускают сервер или клиент автоматически.

## 🚀 Запуск

После успешной установки откройте терминал в корне репозитория.

### 1. Запуск сервера

```bash
dotnet run --project LANChat.Server
```

По умолчанию сервер использует порт:

```text
5000
```

### 2. Запуск клиента

В другом терминале:

```bash
dotnet run --project LANChat.Client
```

### 3. Подключение

В клиенте укажите:

| Поле        | Значение                                      |
| ----------- | --------------------------------------------- |
| **IP**      | IP-адрес компьютера с сервером                |
| **Порт**    | `5000`                                        |
| **Никнейм** | Любое имя                                    |

Для запуска клиента и сервера на одном компьютере можно использовать:

```text
127.0.0.1
```

Для подключения с другого компьютера в той же сети необходимо указать локальный IP компьютера, на котором запущен сервер. Если компьютеры находятся в одной сети, но подключение не работает, проверьте настройки firewall и доступность портов `5000` (TCP) и `5001` (UDP discovery).

## 📡 Протокол

LANChat использует собственный простой протокол поверх **TCP/IP**.

Данные передаются в формате **JSON**.

Пример сообщения:

```json
{
  "type": "message",
  "sender": "User",
  "content": "Привет всем!",
  "timestamp": "2026-09-05T19:00:00Z"
}
```

### Типы сообщений

| Тип       | Назначение                                    |
| --------- | --------------------------------------------- |
| `join`    | Подключение пользователя и установка никнейма |
| `message` | Обычное сообщение                             |
| `leave`   | Отключение пользователя                       |
| `system`  | Системное уведомление                         |

## 🔄 Как это работает

```text
┌──────────────┐
│   Client 1   │
└──────┬───────┘
       │
       │ TCP
       ▼
┌──────────────────┐
│   LANChat.Server │
└──────────────────┘
       ▲       ▲
       │       │
     TCP       TCP
       │       │
┌──────┴───┐ ┌─┴──────────┐
│ Client 2 │ │  Client 3  │
└──────────┘ └────────────┘
```

Сервер является центральной точкой соединения:

1. Клиент подключается к серверу.
2. Клиент отправляет свой никнейм.
3. Сервер регистрирует пользователя.
4. Пользователь отправляет сообщение.
5. Сервер получает сообщение.
6. Сервер рассылает его другим подключённым клиентам.

## 🔐 Безопасность

На данный момент LANChat предназначен прежде всего для использования в доверенной локальной сети.

Протокол не следует считать защищённым от прослушивания, если соединение не дополнено шифрованием.
